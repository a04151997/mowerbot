| −1.26 | (0.04, +1.20) / 45.20 | (0.00, +1.07) / 49.20 | PathDist +1.6、GoalAlign +1.2、GoalDist +1.2 |
| −0.76 | **(0.66, +1.20) / 45.80** | (0.00, +0.95) / 47.80 | GoalAlign +6.0、GoalDist +4.8 |
| −0.51 | (0.70, +1.20) / 43.60 | (0.00, +1.20) / 56.00 | GoalAlign +9.6、GoalDist +8.4 |
| −0.26 | (0.70, +1.20) / 38.80 | (0.00, +1.20) / 62.80 | GoalAlign +10.8、GoalDist +10.8 |

整個 3 秒視窗（65 筆評估）平均「原地 − 選中」的分差：

| critic | 平均分差（正 = 原地吃虧） |
|---|---|
| **GoalAlign** | **+3.63** |
| **GoalDist** | **+3.42** |
| PathDist | +0.57 |
| RotateToGoal | 0.00 |
| Oscillation | 0.00 |
| **BaseObstacle** | **0.00** |

讀法：
* 讓弧線勝出的是 **GoalAlign 與 GoalDist**：往前開的軌跡末端離目標更近、車頭前方的投影點更靠近目標方向，分數比原地轉低。
* **BaseObstacle 在選中與原地兩邊都是 0.0**：它只評分軌跡上**後輪軸那一點**所在的格子，那一點從頭到尾都在自由格（3 節）。
* RotateToGoal 只在接近終點時才作用（`lookahead_time: -1.0`），割草線起點它不參與（0.0）。
* 有效候選數在碰撞前 0.5 s 從 419 降到 356 ~ 383：被判無效的是「後輪軸那一點」會進入 inscribed 帶的軌跡，**不是車頭角會撞牆的軌跡**。

| 遮擋 | 66°（−32.6° ~ +32.6°） | 0° |

### 5.1 遮擋角度對 lidar_z_ground 的敏感度

**不是斜率，是懸崖。** 在方塊模型裡，遮擋只取決於「掃描面在不在方塊高度範圍內」：

* 掃描面高於引擎頂與車體頂：**0°**，每 1 cm 差 **0°**。
* 一旦低於引擎頂（且光達在引擎前 / 後）：立刻跳成整個引擎的水平張角 **2·atan(引擎半寬 / 光達到引擎近面的距離)**，
  與低了多少無關：

  | 光達到引擎近面 d | 0.02 | 0.05 | 0.10 | 0.15 | 0.20 | 0.25 | 0.30 | 0.35 | 0.40 m |
  |---|---|---|---|---|---|---|---|---|---|
  | 遮擋角 | 169.8° | 154.9° | 132.1° | 112.6° | 96.7° | 84.0° | 73.7° | 65.5° | 58.7° |

  （上一輪 d = 0.35 → 65.5°，Gazebo 實測 66.2°，差在 1° 的射線解析度。）
* 一旦低於車體頂（body_height）：**360° 全瞎**（這一輪中途 body 0.70 / 光達 0.55 時實測 360 / 360 條）。

所以「每 1 cm 差幾度」在門檻兩側都是 0，**在門檻上是 0 → 59° ~ 170°（引擎）或 0 → 360°（車體）的跳變**。
決定性的量不是 lidar_z_ground 本身，而是它與門檻的**差**：

> lidar_z_ground − max(engine_top_z_ground, body_height) = 0.55 − 0.50 = **+0.05 m**

三個數字**全部是照片目測**。任何一個估錯 5 cm，結論就翻轉。
（實際引擎頂不是平的：油箱蓋、空濾蓋、拉繩把手各有高度，門檻附近幾公分內會是「部分角度被擋」，方塊模型表現不出來。）

### 5.2 在什麼高度組合下會重新出現遮擋

| 條件 | 結果 |
|---|---|
| lidar_z_ground ≤ body_height（車體方塊頂） | **360° 全瞎**；載入器現在會直接拒絕啟動（`_consistency()` 第 1 項） |
| lidar_z_ground ≤ engine_top_z_ground，且光達在引擎前後範圍內（目前 lidar_x 0.22 ~ 0.38 全部落在引擎 x 0.20 ~ 0.55 內） | 光達在引擎體積內，物理上不可能；載入器拒絕（第 3 項）。代表 lidar_x、engine 尺寸至少有一個估錯 |
| lidar_z_ground ≤ engine_top_z_ground，且光達在引擎後方（使用者描述「光達裝在引擎與電池之間」比較接近這種） | 遮擋 2·atan(0.225 / d)，見 5.1 表；載入器放行並警告 |
| lidar_z_ground > max(engine_top, body_height) | 0° |

注意第二、三列的矛盾：照片描述「光達在引擎與電池之間」（水平方向分開），
但目前的估計（引擎以曲軸 0.375 為中心、長 0.35；光達 0.30）讓光達落在引擎的前後範圍裡。
兩者不能同時成立 —— lidar_x 的基準點確認之後就會知道是哪一個。

### 5.3 現場目視「沒有擋住」作為證據的強度

**中等偏弱，只能排除最大的那一種遮擋。**

* 能排除的：引擎整塊擋在光達窗口前面（上一輪模型那種 66°）。人站在旁邊看得到引擎頂是否高過光達窗口，這種程度的遮擋目視可靠。
* 不能排除的：
  1. **細的東西**：鋁架立柱、線材、油箱蓋、空濾蓋、拉繩把手。2D 光達的掃描面只有幾公釐厚，幾度的遮擋目視看不出來。
  2. **剛好在門檻附近**：如果引擎最高點與掃描面只差 1 ~ 2 cm，站著往下看分不出誰高誰低（視差）。
  3. **後方**：目視多半看前方；光達後面的電池、鋁架、控制盒是否擋住後方幾度，沒有被確認。
* 目視是二元、定性的；它不能告訴我們遮擋幾度、在哪個方向。
* 決定性的證據：光達驅動接起來之後，車停空曠處跑 `python3 test/tools/scan_fov.py 4`（5 分鐘），直接列出被遮擋的角度範圍。
  在那之前，「沒有遮擋」只能當作「最大的那種遮擋大概不存在」。
